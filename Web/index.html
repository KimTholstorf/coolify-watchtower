How it works

You add one task. It does the rest.

No new dashboard to learn. The settings live where you already work: in Coolify.

01

Opt in

Add a scheduled task called watchtower to a service. Its schedule is the update schedule.

02

It checks

On schedule, it compares your running images with the registry. If nothing's new, nothing happens.

03

Coolify updates

If there's a newer image, Coolify pulls it and restarts the service. It shows up in your deployment history.

Why not Watchtower?

Coolify stays in charge.

Watchtower is great on plain Docker. On a Coolify server it gets in the way.

Watchtower

  • Swaps containers behind Coolify's back
  • Coolify never hears about it
  • Needs write access to Docker

coolify-watchtower

  • Asks Coolify to do the update
  • Every update is in your deploy history
  • Only reads from Docker

Plain Docker host? Use Watchtower, maintained by Nick Fedor.

The details

The fiddly bits, handled.

It's one small container. Here's what it takes care of.

Read-only

Docker access goes through a read-only proxy. All changes go through Coolify.

Real versions

Messages say 2.5.4 → 2.5.5 instead of a wall of digests.

Your timezone

Schedules follow your server's timezone in Coolify. 04:30 means 04:30.

Self-updating

It keeps itself current too. Daily, unless you say otherwise.

Apps too

Works for services and Docker Image applications.

Heads-up

Add a service, remove one or change a schedule, and it tells you.
